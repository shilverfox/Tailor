# 待统一修复：用户实机问题清单 — 2026-07-17

状态：**已实施首轮修复；待真实设备照片库回归。**

## UIR-001｜重启后参考照槽位显示占位图

**首轮修复（2026-07-17）：** 已在页面重建时按持久化 identifier 从 PhotoKit 重新加载缩略图；首次选择也改为顺序加载，确保照片与槽位顺序一致。

- **现象：** 首次选取并扫描成功后，重新打开 App 进入“Reference photos”，已选槽位和删除按钮仍在，但真实缩略图变为系统图片占位符。
- **已确认原因：** `PetProfile.referenceAssetIdentifiers` 会持久化 `PHAsset.localIdentifier`，但 `ReferencesFeatureView.thumbnails` 是未持久化的 `@State`。首次选择只从 `PhotosPickerItem.loadTransferable` 填充这个内存数组；页面重新创建时没有按已保存 identifier 从 PhotoKit 重新请求缩略图。
- **产品判定：** 不是原图或扫描结果应被删除的合理行为；应恢复缩略图。若权限收回、原图删除或 iCloud 资源暂不可用，应显示可解释且可恢复的状态。
- **修复验收：** 冷启动、返回页面、前后台切换后，授权范围内的 3–5 张参考照均显示；受限/缺失资源给出明确提示且可重新选择。

## SCN-001｜成功扫描后再次进入仍重跑全量相册

**首轮修复（2026-07-17）：** 成功扫描后不再删除 checkpoint；本地持久化已处理 asset identifiers。重开完成档案不会进入扫描页；相册目录变化后的显式刷新跳过已处理 identifier，仅对新资产请求像素和 Vision 识别。

- **现象：** 已完成一次约 8,927 张的扫描并产生候选/选择结果后，再次使用扫描入口仍从 0 开始处理全相册。
- **产品方案要求：** PRD 第 29 行要求 `draft`、`scanning`、`ready` 档案可“稍后继续”，退出、切后台、锁屏和暂停后保留本地状态；v1 不做后台自动扫描。产品信息架构还规定“重新扫描新增照片”，含义应是显式、增量操作，而非每次重新全量扫描。
- **已确认实现原因：**
  1. `ScanArchiveMergePolicy.completing` 在成功后将 `scanCheckpoint` 设为 `nil`。
  2. 后续 `startScan()` 用 `checkpointForIncrementalRescan` 生成 `nextAssetIndex = 0`、无 `assetCatalogFingerprint` 的 checkpoint。
  3. `ScanResumePolicy.startIndex` 只有 checkpoint 指纹与当前相册目录完全相等时才恢复 cursor；无指纹必然返回 0。
  4. 当前逻辑可以合并并保留既有照片决定，但仍会遍历全量相册，不能称为增量扫描。
- **修复方向：** 成功扫描后持久化“已完成目录指纹 + 已索引 asset identifiers/特征索引版本 + 扫描审计摘要”；正常打开 `ready/exported` 档案直接进入既有确认、时间线或档案，不自动扫描。仅用户点“重新扫描新增照片”时，以本地索引差集扫描新增或变化 asset；库发生删除/权限变化时安全地剔除不可访问资产，保留人工决定的审计记录。
- **修复验收：**
  1. 完成扫描、人工确认、杀掉 App 后重新打开：不进入扫描页，不重复全量计算，既有选择/章节/相册均存在。
  2. 没有新增照片时主动“重新扫描新增照片”：显示 0 张新增并很快完成，不遍历历史 8,927 张。
  3. 新增 N 张照片后主动重扫：仅处理 N 张（及必要的授权/删除校验），原有人工选择不被重置。
  4. 中断中的扫描仍从已持久化 cursor 恢复；不把它误当成功扫描。

## UIR-002｜照片确认页滚动到底部后抖动 / 回弹

**首轮修复（2026-07-17）：** 缩略图加载由 opportunistic 双回调改为单次高质量回调，减少长网格滚动过程中由降质/全质量切换带来的状态风暴。现有长网格 UI 回归通过；仍需真实照片库验证。

- **现象：** 在照片确认（Review）页滚到长网格的最下方、靠近“Choose each photo / Create timeline”区域时，纵向滚动出现持续抖动或无法稳定回滚。
- **当前代码核查：** 当前工作区的 `ConfirmFeatureView` 已把主按钮放进同一个 `TailorScreen` 纵向 `ScrollView`，而不是 `safeAreaInset` 悬浮层；照片网格也使用固定正方形 frame 来避免缩略图回调改变高度。因此截图本身不足以确认真机是否已安装该版本，或是否仍有异步缩略图/嵌套手势造成的运行时问题。
- **待修复范围：**
  1. 增加可在设置页查看的构建版本 / git short SHA，确保真机包可追溯。
  2. 在同一真实照片库上复现并记录滚动 offset、缩略图加载和状态更新次数。
  3. 去除导致滚动容器内容尺寸重复变化的异步更新；保证 Review 页只有一个纵向滚动容器，底部 CTA 不抢占 pan gesture。
- **修复验收：** 有 100+ 张候选、首批缩略图仍在加载、切换分组/年份后，滚到底部和反向上滑均连续稳定；CTA 可点击但不拦截滚动手势。

## EDT-001｜相册编辑器：初始选中、布局工具、页码索引与图片选中态

**首轮修复（2026-07-17）：** 已在首个 body pass 建立首页选中态；页码 rail 统一为固定宽度与间距；封面等不支持换布局的页面点击 Layout 会给出原因；图片选中态加强为高对比边框、手柄和 `PHOTO SELECTED` 标签。

- **现象：** 编辑器首次进入时，底部页码索引可能未立即显示第 1 页选中态；底部 Layout 点击无响应；页码索引项间距不均；画布图片没有足够明确的可见选中态。
- **当前代码核查：**
  1. `selectedPageID` 在 `onAppear` 后才设为首页，首帧会有空选中状态，需在渲染前完成默认值或提供同步派生状态。
  2. Layout 现被 `canChangeLayout` 限制为仅 `photoSelection` 页面可用；截图是封面页，因此按钮视觉上存在但实际被 disabled。这与用户“按钮点击无效”的感知不一致，需明确禁用说明，或按产品决策支持封面/章节页的布局变体。
  3. `ThumbnailRail` 仅约束卡片本体为 42pt，包含不同长度页类型标签的 `VStack` 没有固定总宽度，造成索引视觉间距不均。
  4. 图片元素已有点击设置 `selectedElementID` 与 2pt 边框的底层逻辑，但编辑画布同时存在纸张安全区/文本框边界，现有选中反馈不够独立清晰，用户无法可靠分辨“图片已选中”。
- **修复验收：**
  1. 编辑器首帧即高亮当前第一页，并与顶部页码一致。
  2. Layout 对当前页面有明确可用能力；若不支持，显示原因，不保留“看似可点”的控件；支持时选择布局后实际更新画布并可撤销。
  3. 所有页码索引卡片占相同宽度、标签截断/换行规则一致，横向滚动节奏均匀。
  4. 点击图片后出现独立于安全区的高对比选中框/控制点，并且 Photo 工具明确针对该图；点击文本可切换到文本选中态。
