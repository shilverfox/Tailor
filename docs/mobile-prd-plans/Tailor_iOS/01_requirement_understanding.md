# Tailor v1.1 需求理解与变更基线

## 输入与范围

| 输入 | 路径 | 结论 |
| --- | --- | --- |
| 更新 PRD | `Tailor_v1_PRD.md` | 本轮唯一产品基线；iOS 17+、仅 iPhone |
| 当前工程 | `Tailor/` | 已有 PhotoKit、SwiftData、StoreKit 2、本地 PDF 和 12 页流程 |
| 旧规划 | 同目录 `01`–`06` | 仅作历史参考，已由本轮文件替代 |

Tailor 是用户主动启动的、端侧运行的宠物照片整理工具，不是治疗、提醒或自动回忆产品。v1 不得注册或发送通知，也不得因离开年份、相册变化、冷启动、回前台或时间事件自动展示旧照片。

## 本轮变更目标

1. 给每张候选照片增加敏感处置与永不使用语义；保守降级，不推断病情或死亡原因。
2. 让确认、时间线、章节、预览、PDF 共享同一套“可用照片”过滤规则。
3. 未购买预览固定为 6–8 页真实、带水印样章；购买后以同一内容生成无水印完整 PDF。
4. 用户可隐藏时期/章节并随时安全退出、稍后主动继续。

## 页面影响矩阵

| 页面 | 本轮改动 | 关键验收 |
| --- | --- | --- |
| 05 扫描 | 只在用户点击后扫描；不通知；无法可靠判断敏感时按低置信普通候选 | 无自动启动、无通知注册 |
| 06 确认 | 增加敏感待确认；可标记“稍后决定”“永不使用” | 非 normal/selected 照片不会进入后续素材池 |
| 07 时间线 | 时期/章节隐藏；隐藏后无代表图、预览/PDF 不可见 | 恢复后才重新可见 |
| 08 章节编辑 | 只展示可用照片；用户说明不自动生成 | 永不使用素材不可被重新加入 |
| 09 预览 | 6–8 页带水印真实样章，包含封面、目录、至少两章节、选片和结尾 | 所有展示照片均来自可用素材 |
| 11 PDF | 无水印完整 PDF 与同一素材规则一致 | 敏感、永不使用、隐藏期不渲染 |
| 12 档案 | 暂停/退出后仅由用户再次打开继续 | 无本地通知/自动唤起 |

## 数据与状态

`ArchivePhoto.sensitivityState`: `normal / needsSensitiveReview / hiddenUntilUserDecides / neverUse`。

`neverUse` 是本档案内的永久排除：立即从章节、封面、样章和 PDF 移除，不动系统照片。`hiddenUntilUserDecides` 也不进入后续页面；用户可显式恢复为 normal 后再确认。`excludedReason` 记录用户排除的本地原因，不上传。章节沿用有序 `photoIDs`，首张即封面。

可用素材谓词：`decision == selected && sensitivityState == normal && !hiddenByPeriod`。

## 已知 P0 / 工作策略

敏感素材自动分类模型尚未评审。本迭代只实现数据语义、人工处置和保守入口：无法可靠判断时放入普通低置信候选；不会把医院、病情、临终或死亡原因写入 UI 文案或自动结论。正式视觉资产与 6–8 页 PDF 性能预算由设计/研发并行产出后冻结。

## 2026-07-15 照片确认可发现性修正（P0）

真实用户验证发现：用户在确认页只看到高确定照片，未发现待确认照片的“选入档案”入口；排除一张高确定照片后直接创建时间线，成品只剩一张照片。该问题不得通过隐藏的长按菜单解决，以下规则为本轮实现、设计和验收的共同基线：

1. `Needs review` 必须是页面内可见且可点击的分组入口，显示待确认数量；首次到达确认页时，若存在待确认照片，页面必须以文字明确提示其数量和处理目的。
2. 待确认照片必须提供可见的主操作。用户点击任一待确认缩略图后，立即进入原图/详情确认态，并在底部固定显示 `This is {name}` 与 `Not {name}` 两个操作；不得要求用户知道或使用长按、上下文菜单才能选入或排除。
3. `This is {name}` 将照片设为 `selected`，`Not {name}` 设为 `excluded`；操作后计数、分组和缩略图状态即时更新且本地持久化。长按菜单可以作为辅助入口，但不得是唯一入口。
4. 用户点击 `Create timeline` 时，若仍有待确认照片，必须先显示决策提示：明确展示“已确认 N 张、仍有 M 张待确认”，提供 `Continue reviewing`（直接切换到待确认分组）和 `Create with N photos` 两个可见选择；不得静默跳过待确认照片。
5. 允许用户明确选择仅用已确认照片创建时间线；此时后续时间线、预览和 PDF 仍只使用 `selected && normal && !hiddenByPeriod` 的素材。提示不得以焦虑、催促或哀伤营销文案驱动用户继续处理。

6. 当待确认候选较多时，必须提供可见的 `Select` 批量确认模式：用户可浏览缩略图后逐张勾选，或显式选择当前筛选结果，再执行 `Add N to archive` 一次性选入。批量选入必须由用户主动触发，不能在扫描完成后自动发生；“不是它”仍在单图详情中用于排除明显错误候选。
7. 扫描结果进入待确认前必须同时满足物种检测与参考照相似度门槛。通用动物标签或弱相似度不足以成为候选；猴子、小熊猫、人像等非目标猫狗不得显示为“你的宠物候选”。保守过滤造成的漏检可由手动选图补充，不能以降低门槛换取错误候选。

该修正不改变“低置信不自动入册”的安全规则，而是让人工确认路径可发现、可理解、可逆。首次使用者在不接受口头指导的情况下，应能从确认页找到待确认照片、完成“这是/不是”决策，或理解并明确选择仅以当前已确认照片继续。
